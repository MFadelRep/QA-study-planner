# Senior QA Automation + MLOps — Master Plan

## Outcome
By Hour 45, the learner can design, implement, validate, automate, containerize, execute, observe, secure, and explain a senior-level QA automation + MLOps platform.

## Execution model
Build → Check → Learn on demand → Fix/Verify → Continue.

## Project
One coherent AI QA Platform is the primary learning vehicle. Avoid unrelated toy exercises when the same capability can be proven in the project.

## Required capability coverage
- Playwright: maintainable architecture, fixtures, POM, configuration/projects, authentication/state reuse, API/UI hybrid flows, network interception/diagnostics, isolation, traces/artifacts, flake diagnosis.
- API: request construction, authentication, status/header/body assertions, schemas/contracts, positive/negative/boundary cases, chaining, data setup/cleanup, API-to-DB verification.
- AI QA: nondeterministic test-oracle strategy, hallucination/misinformation controls, robustness, groundedness, safety boundaries, latency/cost awareness, regression evaluation.
- RAG: measurable retrieval and answer signals, adversarial/regression datasets, grounding and citation/support checks.
- MLOps: reproducibility, dataset/model lifecycle, experiment tracking, metrics, artifacts, quality gates, registry/promotion, rollback.
- Security: authentication/authorization, sessions/tokens, secrets, web/API risks, SAML/SSO, SSRF/injection/access-control reasoning, CI security checks.

## 45-hour scope
### 1–4 Foundations
Programming + Terminal + Git; TypeScript for automation; async/testable code; Git + CI survival.

### 5–15 Playwright + API + Data
Playwright foundations; architecture; API/auth; network/reliability; advanced Playwright; API strategy; SQL; PostgreSQL test data; advanced SQL; integration validation; architecture review.

### 16–19 CI/CD
CI/CD foundations; GitHub Actions; GitLab CI/CD; test reporting.

### 20–23 Performance
Performance concepts; JMeter; Locust; performance analysis.

### 24–29 Containers + Kubernetes
Docker fundamentals; Docker Compose; containerized CI; Kubernetes fundamentals; Kubernetes test execution; Kubernetes reliability.

### 30–35 AI QA + RAG
AI QA foundations; AI-assisted QA; RAG basics; RAG evaluation; AI inference testing; AI QA Platform integration.

### 36–38 MLOps
MLOps foundations; MLflow; MLOps CI/CD.

### 39–45 Senior QA + Interview
Senior QA strategy; reliability/flakiness; security for QA; scalability/governance; capstone hardening; interview engineering; final simulation.

## Evidence standard
A capability is complete when there is observable project evidence, a verified result, or a clear technical explanation tied to an implemented result. Reading alone is not completion.

## Plan-change rule
The plan may evolve when the project exposes a better engineering path, tooling constraint, or genuine knowledge gap, but required 45-hour outcomes must not be silently removed.
